# Экспериментальный стенд Deskhand — практические работы 3 и 4

Исследование сокращения истории наблюдений AI-ассистента: сколько байтов
повторно включается в контекст и сохраняются ли последние нужные наблюдения.
Все материалы работы находятся в **этом отдельном репозитории**.
Исходный [Deskhand](https://github.com/BobrAll/deskhand) использован только для чтения.

## Что именно измеряется

SUT — Python-порт политики `trimmedHistory` из Deskhand,
commit `5514b8226ab47ddfc362360659eff252d22f9c69`.
[Происхождение и лицензия](vendor/deskhand/README.md).
Это компонентный эксперимент на **синтетических наблюдениях**, не запуск
полного macOS-приложения и не оценка успешности LLM-агента.
Байты payload не равны токенам, стоимости API или полному HTTP-трафику.

`full` сохраняет всю историю. `bounded` оставляет последнее дерево каждого
из трёх последних приложений, последнее сообщение с изображением и последний diff.
Устаревшие блоки заменяются маркерами; обычный текст сохраняется.

## Воспроизведение

Нужны Git, Make, Python 3 на хосте, Docker Engine/Desktop и Compose v2.
Первый запуск скачивает зависимости; эксперимент работает без сети и API-ключей.
Контейнеры ограничены 2 CPU и 1 GiB RAM. Docker VM желательно выделить от 4 GiB.

```sh
git clone https://github.com/BobrAll/pyweb3-4.git
cd pyweb3-4
make verify                          # проверка опубликованного архива
make smoke                           # тесты и 20 сокращённых прогонов
make experiment                      # 120 основных + 10 A/A, затем анализ
make repeat                          # ещё один полный batch с нуля
make down
```

Одна команда полного эксперимента — `make experiment`. Все параметры находятся
в [configs/experiment.json](configs/experiment.json). Новый процесс SUT создаётся
для каждого прогона; два прогревочных прохода исключаются из измерений.
Порядок 130 запусков перемешивается фиксированным seed.

Каталоги batch намеренно не перезаписываются. Для повторения используй новое имя:

```sh
make experiment BATCH=my-run
make analyze BATCH=my-run
```

Результаты: `results/raw/<batch>/` — manifest и сырые измерения каждого шага;
`results/processed/<batch>/` — JSON/CSV, таблица и графики. Незавершённый batch
не анализируется. Во всех парах вход одинаков, но повторы имеют разные seeds.

## Проверки

```sh
make test                            # функциональные тесты и калибровка статистики
python3 -m scripts.check_swift_parity # опционально: установленный Swift compiler
```

Дифференциальная проверка сравнивает Python с неизменёнными телами функций Swift
на 103 случаях. Полный эксперимент включает A/A 5+5, проверку структурных
инвариантов, CPU оркестратора и тренд времени. Генерация входов завершается до
старта измерений. Метрика CPU — расход CPU процесса-оркестратора за время ожидания
дочернего SUT, в процентах одного ядра, а не CPU всего контейнера.

Для байтов при одинаковых версиях/конфиге допустимое расхождение равно нулю.
Тайминги зависят от машины; совпадение миллисекунд не требуется. Не следует
считать p ≥ 0,05 в A/A доказательством эквивалентности.

[GitHub Actions](.github/workflows/experiment.yml) выполняет `make smoke` и
публикует результаты как artifact. Статус удалённого CI проверяется отдельно
от локального выполнения.

## Опубликованные данные

[Архив измерений](data/measured-results.tar.gz) содержит основные, повторные и
smoke-прогоны, манифесты, обработанные результаты и Swift-проверку.
[SHA256SUMS](data/SHA256SUMS) фиксирует архив и описание базового образа.

Для повторного анализа сохранённых измерений сначала распакуй архив в чистую
папку репозитория (он содержит только `results/`), затем выполни `make analyze`.
Для нового эксперимента выбери другое имя batch, чтобы сохранить исходные записи.

```sh
tar -xzf data/measured-results.tar.gz
make build
make analyze BATCH=main
```

В manifest записаны исходный Git-коммит, dirty-флаг, hashes исходников, параметры,
seed, UTC-время, машина, Docker и ID образа. Отчётные файлы добавлены после
измерений, поэтому финальный Git-коммит естественно отличается от измеренного.

## Сборка отчётов

Для PDF дополнительно нужны `reportlab` и шрифт Arial (macOS) либо DejaVu Sans
(Linux). Это не зависимости эксперимента. Выполни `python3 scripts/build_reports.py`.
Графики в отчётах берутся из `docs/figures/`; исходные тексты — Markdown/JSON.

Исходный Swift-фрагмент и производный Python-порт используются в учебных
некоммерческих целях по PolyForm Noncommercial 1.0.0. Лицензия сохранена рядом
с фрагментом. В репозитории нет реальных снимков экрана, промптов пользователя
или API-ключей.
